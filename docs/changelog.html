Changelog

Every change to kosha, newest first. Releases are git tags (all tags, GitHub releases); the source of this page is CHANGELOG.md.

v0.3.02026-10-21release ↗

You see what kosha is doing for each package, at every step.

  • A live board per step: one row per package, with what it's doing right now ("checking v0.1.3…", "cloning…", "fetching v0.1.5…", "checking out v0.1.5"), then its result and how long it took; a footer counts done, running, waiting and failed, with the time so far. Long lists fit the screen (running rows first). update and install check every package this way before showing the plan; list, outdated, remove and doctor use it too.
  • -v / --verbose: every step as a timestamped line, and every git command with its exit code and time.
  • Doctor: a row per package, then the findings, each with the command that fixes it.
  • The [Y/n] question takes a single key and prints the answer (Yes/No); Esc or Ctrl-C mean no.
  • Robust: one kosha changes things at a time (a lock); an interrupted or failed clone leaves no half-made folder; Ctrl-C marks what didn't finish as cancelled and restores the cursor; offline and missing-repository errors say so in plain words; git that hangs times out.
  • Tab completion asks kosha for package names instantly (kosha _names), never the network.
  • Linted with ruff (ruff.toml; CI runs it). The site builder no longer needs Python 3.12.

v0.2.02026-10-21release ↗

A new interface, faster, and help for every command.

  • Looks like nala: boxed tables, a full-width header per step, coloured status (● up to date, ▲ update, ● pinned, ◆ linked), and a summary line (Summary: Install 2 · Upgrade 3). Install, update and remove show what will happen first and ask Do you want to continue? [Y/n] (-y skips it; scripts without a terminal aren't asked).
  • Live progress: downloads run in parallel, one animated line per package, ending in ✓ or ✗; then each update's changelog under "What's new in …", and the total time.
  • Faster: newest releases are remembered for 15 minutes (-r asks again), every package's version is read in parallel, clones are blobless, and installs download everything at once before finishing in dependency order. kosha list takes about 0.2 s with a warm cache.
  • Help: kosha help groups every command (Find, Install, Maintain, Develop, Help) with options and examples; kosha help <command> or kosha <command> --help shows one command in detail; a mistyped command or package suggests the right one ("did you mean kosha install?").
  • Aliases: ls, find, show, i, add, up, upgrade, rm, log, check.
  • Tab completion: kosha completions zsh|bash (commands and package names).
  • -q for quiet output, --no-color (or NO_COLOR).

v0.1.02026-10-21release ↗

First release.

  • list, search, info, install (newest release, or pkg@version to pin), update (everything, in parallel, with each tool's changelog since your version), outdated, remove, pin/unpin, link/unlink (run a development checkout), changelog, doctor, refresh, self-update.
  • Dependencies are installed first and protected from removal.
  • Tools already on disk are adopted as they are.
  • Missing programs are reported, and on Arch offered for install through anumati.
  • The registry: Vyom and its fourteen tools, nāda, anumati, sangam, kosha.
  • --json for list and outdated; a no-root installer.
