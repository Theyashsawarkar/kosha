Kosha (कोश) is Sanskrit for "treasury, storehouse": where all the tools are kept.

Vayu's tools each live in their own repository: the Vyom panels and their fourteen tools, nāda, anumati, sangam, and whatever comes next. That keeps each one independent, but leaves you with many clones to keep track of. kosha does it for you: it knows where each tool goes, installs its newest release, installs what it depends on first, checks for updates in one go, shows the changelog when it updates, and lets you pin a version or work on a tool from your own checkout.

#Features

  • One list of everything: kosha list shows every package, the version you have, the newest release, and whether it's pinned, linked or out of date.
  • Released versions: installs and updates move between release tags (v0.1.4), never onto unreleased commits. kosha install ganit@0.1.2 installs and pins an older one.
  • Dependencies first: installing a Vyom tool installs Vyom; removing Vyom is refused while a tool needs it.
  • Updates that tell you what changed: kosha update updates everything in parallel and prints each tool's changelog since your version.
  • Adopts what's already there: tools you cloned by hand (or an older installer did) are recognised and managed as they are, nothing re-downloaded.
  • Safe with your work: a clone with local changes is never updated or removed without --force, and --force stashes rather than discards.
  • Develop in place: kosha link nada ~/code/nada runs your checkout instead of the release; kosha unlink nada puts the release back.
  • System packages: when a tool needs a program you don't have, kosha says which, and on Arch offers to install it (through anumati when it's there).
  • Scriptable: kosha list --json, kosha outdated --json, meaningful exit codes, NO_COLOR respected.
  • No dependencies beyond git and Python 3.11's standard library.

#Install

curl -fsSL https://raw.githubusercontent.com/Theyashsawarkar/kosha/main/install.sh | bash

It clones kosha into ~/.local/share/kosha, links ~/.local/bin/kosha, and needs no root. Or by hand:

git clone https://github.com/Theyashsawarkar/kosha ~/.local/share/kosha
ln -s ~/.local/share/kosha/bin/kosha ~/.local/bin/kosha
kosha install kosha          # kosha manages itself from now on

Then install what you want, e.g. the launcher, the calculator and the music player:

kosha install dvara ganit nada

#Usage

kosha help shows every command, grouped, with examples; kosha help <command> (or kosha <command> --help) explains one. A typo gets a suggestion.

kosha help [<command>]                 every command, or one in detail
kosha list [--installed] [--json]      packages: installed version, newest release
kosha search <words>                   find packages by name or description
kosha info <pkg>                       details, where it lives, what it needs
kosha install <pkg>[@version] ...      install (newest release, or a pinned one) with its dependencies
kosha update [<pkg> ...] [--force]     update to the newest release (everything, without names)
kosha outdated [--json]                what has a newer release
kosha remove <pkg> ...                 uninstall
kosha pin <pkg> | unpin <pkg>          keep a package on its version / let it update again
kosha link <pkg> <path> | unlink <pkg> use a development checkout in place of the release
kosha changelog <pkg> [<from>]         what changed (since a version)
kosha doctor                           check every installed package
kosha refresh                          download the newest package list
kosha self-update                      update kosha itself
kosha completions zsh|bash             tab completion for commands and packages

Options: -y/--yes (don't ask), -v/--verbose (every step and git command), -q/--quiet, -r/--refresh (ask GitHub now),
         --json (list, outdated), --no-color (or NO_COLOR=1)

#How it works

  • The registry (registry.toml) lists every package: its repository, kind, dependencies, the commands it needs and the Arch packages that provide them, and an optional command to run after installing. kosha uses whichever is newer of the copy it shipped with and the one kosha refresh downloaded.
  • A package is a git clone in the folder its kind prescribes. A version is a release tag; installing checks out the newest, updating fetches and checks out a newer one. Newest releases are asked of GitHub with git ls-remote (no clone needed), all packages in parallel.
  • The checkout is the truth. kosha reads the version from git, so a tool updated by hand is still reported correctly. ~/.local/state/kosha/installed.json only adds what git can't know (pinned, linked); history.log next to it records every install, update and removal.
  • Post-install commands run in the package's folder (anumati's install.sh, which installs it root-owned and asks for your password).

The design decisions, with their reasons, are on the website.

#Adding a package

A pull request adding a table to registry.toml:

[packages.mytool]
repo = "you/mytool"            # GitHub owner/name, or a full git URL
kind = "vyom-tool"             # vyom | vyom-tool | app | tmux-plugin
description = "One line: what it is"
requires = ["vyom"]            # other kosha packages
commands = ["qalc"]            # programs it needs on PATH
arch = ["libqalculate"]        # Arch packages that provide them
post = "./install.sh"          # optional: run after install and update

The repository needs release tags (v1.2.3) and a CHANGELOG.md with one ## v1.2.3 section per release, which kosha update prints. CI checks the registry is valid.

#Troubleshooting

  • "has local changes". Commit or stash them in the folder kosha names, or kosha update --force (stashes them; git stash pop brings them back).
  • "couldn't check". GitHub was unreachable for that package; the rest still updated. Run it again later.
  • A command isn't found after installing. ~/.local/bin must be on your PATH; kosha doctor says so.
  • anumati's update asks for a password and fails in a script. Its installer needs sudo: run kosha update anumati in a terminal.
  • Anything else: kosha doctor, and ~/.local/state/kosha/history.log.
